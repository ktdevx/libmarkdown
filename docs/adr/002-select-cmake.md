# ADR-002: CMake をビルドシステムとして選定する

## ステータス

承認

## 背景

libmarkdown は C99 で実装するライブラリであり、Linux、Windows および macOS で configure、build、test を実行できるビルドシステムが必要である。ビルド設定とテスト実行方法を共通化し、開発環境と CI で同じ手順を利用できるようにする必要がある。

どのビルドシステムを libmarkdown の標準として採用するか決定する必要がある。

## 決定

「CMake」を採用する。

CMake の標準的な configure、build、test の流れを利用することで、C99 ライブラリのビルド手順を Linux、Windows および macOS に共通化できる。CI でも同じ CMake の手順を実行し、環境ごとの差異を各ジェネレータおよびツールチェーンに委ねる。

## 検討案

### CMake

クロスプラットフォームのビルドシステム。CMakeLists.txt にビルド構成を記述し、環境に応じて Makefile、Visual Studio プロジェクト、Ninja などのビルドシステムやプロジェクトファイルを生成する。

- 利点: Linux、Windows および macOS を対象とするビルド設定を共通の記述で管理できる。
- 利点: configure、build、test の手順をローカル環境と CI で統一できる。
- 利点: C99 の言語要件とライブラリのビルド設定を一つのビルド構成で管理できる。
- 利点: 複数のビルドツールや開発環境に対応するジェネレータを利用できる。
- 欠点: 利用者の環境に CMake と、選択したジェネレータおよび C コンパイラが必要になる。
- 欠点: CMake の設定記述と運用方法を学ぶ必要がある。

### Make

Unix 系環境で広く利用されているビルドツール。Makefile に依存関係やコンパイル、リンクなどのビルドルールを記述する。

- 利点: Unix 系環境で広く利用されている。
- 利点: 単純なプロジェクトではビルドルールを比較的簡潔に記述できる。
- 欠点: Windows を含む複数の環境で同一のビルド設定を利用するには追加の対応が必要になる。
- 欠点: configure、build、test の環境差を共通の仕組みで管理しにくい。

### Autotools

Autoconf、Automake などで構成されるビルドシステム。configure スクリプトによって、コンパイラやシステム環境を検出してビルド環境を構成する。

- 利点: Unix 系環境における C/C++ プロジェクトで広く利用されている。
- 利点: コンパイラやシステム環境に応じた詳細な configure 処理を構築できる。
- 欠点: Windows を含むクロスプラットフォームなビルド環境の構築が複雑になる。
- 欠点: configure、build、test の仕組みを構築・維持するための学習および運用コストが大きい。

### Meson

クロスプラットフォームのビルドシステム。Meson の設定ファイルにビルド構成を記述し、Ninja などのバックエンドを利用してビルドを実行する。

- 利点: Linux、Windows および macOS を対象とするビルド設定を共通の記述で管理できる。
- 利点: ビルド設定を比較的簡潔に記述できる。
- 欠点: CMake とは異なるビルドシステムおよびツールチェーンを導入・運用する必要がある。
- 欠点: CMake と比較して、プロジェクトで利用する標準的なビルドシステムとしての既存資産や利用経験を活用しにくい。
