# ADR-009: UTF-8 の妥当性を呼び出し側の前提条件とする

## ステータス

承認

## 背景

libmarkdown の公開 API は UTF-8 の Markdown および文字列属性を扱う。

UTF-8 の検証、正規化、置換および文字化けからの回復をライブラリで行うと、解析・編集・シリアライズの各経路に追加の処理と診断規則が必要になる。

UTF-8 の妥当性をライブラリが保証するのか、呼び出し側が保証するのかを決定する必要がある。

## 決定

「UTF-8 の妥当性を呼び出し側の前提条件とする」を採用する。

libmarkdown が扱う文字列を UTF-8 に限定し、その妥当性を呼び出し側が保証することで、ライブラリの責務を Markdown の解析・編集・シリアライズに集中させ、文字エンコーディングの検証や補正をライブラリの責務に含めないため。

## 検討案

### ライブラリが UTF-8 を検証して不正な入力を拒否する

ライブラリが API の入力時に UTF-8 の妥当性を検証し、不正な入力をエラーとして拒否する方式。

- 利点: 呼び出し側が UTF-8 の妥当性を事前に検証する必要がない。
- 利点: 不正な入力をライブラリのエラーとして明確に扱える。
- 欠点: 各入力経路で UTF-8 の検証処理が必要になる。
- 欠点: UTF-8 の検証結果をエラーコードや診断情報として扱うための仕様が必要になる。

### 不正な UTF-8 を置換して処理を継続する

不正な UTF-8 をライブラリ側で別の文字へ置換し、処理を継続する方式。

- 利点: 不正な入力でも処理を継続できる。
- 利点: 解析処理を途中で失敗させずに済む。
- 欠点: 入力内容が暗黙に変更される。
- 欠点: 入力と出力の文字列が一致しない可能性がある。
- 欠点: どのように置換するかを仕様として定義する必要がある。

### UTF-8 の妥当性を呼び出し側の前提条件とする

ライブラリが受け取る文字列は有効な UTF-8 であることを呼び出し側が保証し、ライブラリは UTF-8 の妥当性を検証・補正しない方式。

- 利点: ライブラリの責務を Markdown の解析・編集・シリアライズに集中できる。
- 利点: UTF-8 の検証処理や補正処理をライブラリに持ち込まずに済む。
- 欠点: 呼び出し側が UTF-8 の妥当性を保証する必要がある。
- 欠点: 前提条件に違反した場合の動作を保証できない。
