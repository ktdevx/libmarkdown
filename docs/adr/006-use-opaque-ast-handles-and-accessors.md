# ADR-006: 不透明な AST ハンドルとアクセサ API を使用する

## ステータス

承認

## 背景

libmarkdown は利用者が観察および編集できる公開 AST を提供する。一方、AST は親子関係、所有権、必須属性および UTF-8 に関する不変条件を満たす必要がある。公開構造体を直接書き換え可能にすると、ライブラリがこれらの条件を維持できない。

利用者が AST を観察・編集する公開モデルと、AST の内部表現および不変条件の保護方法を決定する必要がある。

## 決定

「不透明な AST ハンドルとアクセサ API を使用する」を採用する。

利用者が AST の構造や属性を観察し、検証済みの操作で編集できる一方、AST の内部表現を隠蔽して不変条件をライブラリ側で維持できるため。

## 検討案

### 読み取り専用の公開構造体と編集 API を使用する

AST の構造を公開構造体として利用者から読み取り可能にし、編集についてはライブラリが提供する API を介して行う方式。

- 利点: AST の構造を利用者が直接確認できる。
- 利点: 編集操作を API に限定することで、不変条件をライブラリ側で検証できる。
- 欠点: AST の内部表現が公開インターフェースに含まれる。
- 欠点: 内部構造の変更が公開 API に影響する可能性がある。

### 不透明な AST ハンドルとアクセサ API を使用する

AST の内部構造を非公開とし、利用者には不透明なハンドルとアクセサ API を提供する方式。AST の観察および編集は、ライブラリが提供する API を介して行う。

- 利点: AST の内部表現を隠蔽できる。
- 利点: 編集操作をライブラリが管理し、不変条件を維持できる。
- 利点: 内部実装を変更しても公開インターフェースへの影響を抑えられる。
- 欠点: 利用者は構造体のフィールドへ直接アクセスできない。
- 欠点: 観察・編集のためのアクセサおよび操作 API を定義する必要がある。

### 可変の公開構造体を使用する

AST の構造を公開構造体として提供し、利用者が構造体のフィールドを直接読み書きする方式。

- 利点: 利用者が単純なフィールド操作で AST を編集できる。
- 利点: API を介さずに AST の詳細へアクセスできる。
- 欠点: 利用者による変更をライブラリ側で検証できない。
- 欠点: 不正な親子関係や属性などの不変条件を維持することが難しい。
- 欠点: 内部表現の変更が公開 API に直接影響する。
