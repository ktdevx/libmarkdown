# ADR-004: Markdown シリアライズは意味的等価性を保持する

## ステータス

承認

## 背景

libmarkdown は Markdown 文字列を AST に解析し、編集可能な AST を Markdown へシリアライズする。入力 Markdown には、空白、改行形式、記法選択など、文書の意味を変えない複数の表現が存在するため、シリアライズ結果の一致基準を定める必要がある。

シリアライズにおいて、入力 Markdown の字句的な表現を完全に保持するのか、再解析したときの文書構造および意味を保持するのかを決定する必要がある。

## 決定

「AST の意味的等価性を保持する」を採用する。

AST を編集してから再シリアライズするという本ライブラリの目的に適合し、入力時の記法に依存せず、Markdown と AST の相互変換を検証できるため。

## 検討案

### 入力 Markdown の字句的表現を完全に保持する

入力 Markdown の文字列や空白、改行、記法などを可能な限り保持し、AST をシリアライズした結果が元の Markdown と字句的に一致することを目指す方式。

- 利点: Markdown の入力時の表現を維持できる。
- 利点: シリアライズ前後でソースコードの差分を小さくできる。
- 欠点: 入力時の字句情報を AST または別のソース保持機構で管理する必要がある。
- 欠点: AST の編集によって、保持していた字句情報と AST の内容に不整合が生じる可能性がある。
- 欠点: Markdown の複数の等価な表現を区別して保持するため、シリアライザおよび AST の実装が複雑になる。

### AST の意味的等価性を保持する

入力 Markdown を AST に変換し、AST の内容を基準として Markdown を生成する方式。シリアライズ結果を再解析した AST が、シリアライズ前の AST と意味的に等価であることを保証する。

- 利点: AST の編集結果を Markdown として再利用できる。
- 利点: Markdown の入力形式ではなく、再解析後の文書構造および意味を基準に検証できる。
- 利点: ソースの字句情報を保持するための機構を必要としない。
- 欠点: シリアライズ結果は入力 Markdown と字句的に一致しない場合がある。
- 欠点: AST の意味を正しく Markdown に変換するシリアライザの実装が必要になる。

### 意味を保持せず、任意の Markdown を生成する

AST の内容や入力 Markdown との意味的な関係を保証せず、シリアライザが構文的に有効な Markdown を生成する方式。

- 利点: シリアライザの実装を単純化できる。
- 利点: 出力形式に関する制約が少なく、実装上の自由度が高い。
- 欠点: シリアライズ後に再解析すると、元の AST と異なる文書構造や意味になる可能性がある。
- 欠点: Markdown と AST の相互変換による情報保持を保証できない。
- 欠点: AST を編集して Markdown に戻すというライブラリの用途に適さない。
