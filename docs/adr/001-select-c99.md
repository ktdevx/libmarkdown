# ADR-001: C99 を実装言語標準として選定する

## ステータス

承認

## 背景

libmarkdown は、Markdown と編集可能な AST を扱う C 言語ライブラリであり、公開 API と実装が依存する言語標準を固定する必要がある。言語標準を固定しない場合、利用可能な構文、標準ライブラリ、コンパイラおよび対象環境の前提が実装ごとに異なる可能性がある。

どの C 言語標準を libmarkdown の実装および公開 API の基準とするか決定する必要がある。

## 決定

「C99」を採用する。

C99 を実装および公開 API の最低言語標準とすることで、C 言語ライブラリとしての API を維持しながら、C90 より新しい標準機能を利用できる。C11 以降の機能への依存は、C99 に対応する利用者およびビルド環境を不要に制限するため、必須としない。

## 検討案

### C99

1999 年に ISO/IEC 9899 として標準化された C 言語規格。可変長配列、指定初期化子、`//` コメント、`inline` などの機能が追加されている。

- 利点: C90 より新しい言語機能を利用できる。
- 利点: C 言語として公開 API を設計でき、C99 対応環境を利用者の最低要件とできる。
- 利点: CMake の configure、build、test において C99 を共通の言語要件として検証できる。
- 欠点: C11 以降で追加された言語機能や標準ライブラリ機能を必須の実装基盤として利用できない。

### C11 以降

2011 年に標準化された C11 を基準とし、それ以降の C 言語規格で追加された機能も必要に応じて利用する方式。

- 利点: C99 に加えて、C11 以降で追加された言語機能や標準ライブラリ機能を利用できる。
- 欠点: C99 に対応する利用者およびビルド環境を不要に制限する。
- 欠点: C11 以降の機能への依存により、対応コンパイラおよび対象環境の要件が増える。

### C90

1990 年に ISO/IEC 9899 として標準化された C 言語規格。C99 より古い規格であり、C99 で追加された言語機能を利用できない。

- 利点: より古いコンパイラおよび環境を対象にできる。
- 欠点: C99 以降で追加された言語機能を利用できない。
- 欠点: 現代的な C 言語による実装に対して制約が大きい。

### C++

C 言語を基盤として発展したプログラミング言語。クラス、テンプレート、例外、標準テンプレートライブラリなどの C 言語にはない機能を提供する。

- 利点: C++ の型安全機能や標準ライブラリを利用できる。
- 欠点: C 言語ライブラリとしての API を設計するというプロジェクトの前提と一致しない。
- 欠点: C++ を利用できない環境からの利用を制限する。
