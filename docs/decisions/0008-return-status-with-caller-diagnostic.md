# 状態コードと呼び出し側診断オブジェクトを返す

## Context and Problem Statement

libmarkdown の解析、編集およびシリアライズは、不正引数、メモリ不足、AST 不変条件違反などを利用者が識別できる形で報告する必要がある。AST が生成されない解析失敗や、AST を持たないノード生成失敗にも同じ方法を適用でき、スレッド局所状態に依存しないエラー通知モデルが必要である。

公開 API の失敗結果と詳細な診断情報をどのように返すか決定する必要がある。

## Considered Options

* 状態コードだけを返す
* 状態コードと呼び出し側診断オブジェクトを返す
* AST ごとの最終エラーを保持する

## Decision Outcome

Chosen option: "状態コードと呼び出し側診断オブジェクトを返す", because 全ての失敗可能な操作で決定的な状態を返しつつ、AST の有無や共有状態に依存せずに詳細な診断を提供できるため。

失敗可能な公開 API は `md_status_t` を返す。呼び出し側が `md_diag_t` を指定した場合、ライブラリは各呼び出しの結果でその内容を上書きする。診断には少なくとも状態コード、処理段階、入力位置またはノードに関する位置情報、および必要な補足情報を格納する。診断オブジェクトは呼び出し側が所有し、ライブラリがその寿命を延長することはない。診断オブジェクトを指定しない場合でも、`md_status_t` により失敗種別を識別できる。

### Consequences

* Good, because 解析前、解析中、編集時およびシリアライズ時に同一の通知方式を使用できる。
* Good, because グローバル状態やスレッド局所エラー状態を必要としない。
* Good, because 利用者は状態コードだけを必要とする経路で診断の保持を省略できる。
* Bad, because API ごとに診断オブジェクトの上書き契約を文書化する必要がある。
* Bad, because 診断の位置情報が存在しない操作では、その不在を表現する規則が必要である。
