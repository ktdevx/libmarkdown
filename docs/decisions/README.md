# 決定事項

このプロジェクトでは、将来の設計や実装に影響する重要な決定を、アーキテクチャ意思決定記録（ADR）として記録する。

## 記録するタイミング

次のような、将来の設計や実装に影響する重要な決定について ADR を作成する。

* アーキテクチャやシステム構成の変更
* 技術、ライブラリ、プラットフォームの選定
* 公開 API や重要なインターフェースの変更
* データモデル、永続化、通信方式などの設計変更
* 複数の選択肢を比較して決定した事項
* 既存の ADR に記録された決定の変更

局所的な実装変更や、既存の方針に従うだけの変更については、原則として ADR を作成しない。

## 作成とレビュー

1. 可能な限り、実装を始める前に ADR を作成する。
2. MADR のテンプレートを使用する。
3. 背景と問題、検討した選択肢、採用した決定、決定理由を記録する。
4. 関連する課題、仕様書、設計資料がある場合はリンクする。
5. ADR は、関連する変更と同じレビュー単位でレビューする。
6. ADR の内容が承認された後に実装することが望ましい。
7. 緊急の変更などで事前に ADR を作成できなかった場合は、事後にできるだけ早く作成する。

## ファイル名と番号

ファイル名は次の形式とする。

`NNNN-短いタイトル.md`

* `NNNN` は 4 桁の連番とする。
* 連番は既存の最大番号の次の番号を使用する。
* タイトルは決定内容を簡潔に表す英語のケバブケースとする。
* 一度使用した番号やファイル名は変更しない。

## ADR テンプレート

新しいアーキテクチャ意思決定記録（ADR）を作成する際は、以下のテンプレートのいずれかを出発点として使用すること。

* [adr-template.md](adr-template.md) は、各セクションの説明を含む完全なテンプレート。
* [adr-template-minimal.md](adr-template-minimal.md) は、各セクションの説明を含む必須セクションのみのテンプレートです。 <!-- 「### Consequences」も "任意" として含まれている。 -->
* [adr-template-bare.md](adr-template-bare.md) は、すべてのセクションを空にした完全なテンプレート。
* [adr-template-bare-minimal.md](adr-template-bare-minimal.md) は、説明を含まない必須セクションのみのテンプレートです。 <!-- 「### Consequences」も "任意" として含まれている。 -->

MADRのドキュメントは <https://adr.github.io/madr/>、ADR全般に関する情報は <https://adr.github.io/> を参照のこと。
