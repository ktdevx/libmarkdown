# 公開 AST を所有権付きの検証可能な木構造とする

## Context and Problem Statement

libmarkdown は、Markdown の構造と意味を利用者が観察および編集できる公開 AST として提供する。利用者による編集後も AST をシリアライズ可能にするには、ノードの種類、親子関係、所有権および属性の整合性を維持する必要がある。

AST を単なる相互参照可能な公開データとして扱うのか、ライブラリが所有権と構造的不変条件を管理する木構造として扱うのかを決定する必要がある。

## Considered Options

* 不透明な AST とし、利用者は構造を直接観察・編集しない
* 公開 AST の各要素を利用者が自由に変更できるようにする
* 公開 AST とし、検証付きの編集操作で所有権と不変条件を維持する

## Decision Outcome

Chosen option: "公開 AST とし、検証付きの編集操作で所有権と不変条件を維持する", because 利用者による AST の観察・編集を可能にしながら、シリアライズ可能な構造とメモリ所有権を一貫して維持できるため。

AST のルートは `document` ノードとする。各ノードは高々 1 つの親を持ち、親子関係に循環およびノード共有を含めない。親子関係はノード種別ごとに許可された組み合わせでなければならず、必須属性、属性値およびテキスト内容は有効でなければならない。AST には本ライブラリが対応するノード種別だけを含める。

ノードの生成、変更、削除、親子関係の変更および走査は、公開された AST 操作として提供する。編集操作が不変条件を破る場合は失敗し、AST を変更しない。親子関係の変更に成功した場合、親が子の所有権を持つ。既に親を持つノードの追加は失敗し、子の切り離しに成功した場合は所有権を利用者へ移転する。親を破棄すると、その親が所有する子も破棄する。

### Consequences

* Good, because 利用者が AST の構造と意味を観察し、編集後の AST を Markdown にシリアライズできる。
* Good, because 親子関係、所有権および破棄責任を明確にできる。
* Good, because 不正な編集を操作単位で拒否し、失敗前の AST を維持できる。
* Good, because AST の有効性を検証する基準を、実装とテストで共有できる。
* Bad, because 自由なポインタ操作ではなく、ライブラリが提供する編集操作を利用する必要がある。
* Bad, because 親子関係や属性を変更する操作で検証処理が必要になる。
